Release Notes

Version 1.4.0

This section tracks updates for release 1.4.0.

Changes already included

- WSPR now works with CB (11 m) callsigns. Standard WSPR cannot pack a CB callsign: its formats only encode a standard amateur callsign into 28 bits, and the only alternative (a 15-bit hashed callsign) can be resolved by a receiver just if it was previously learned from a decodable standard transmission, which a CB callsign can never send. Plain WSPR would therefore only ever show "<...>" for CB stations.
- WSPR mode is now CB-only in WSJT-CB and uses a dedicated, self-contained source encoding: the CB callsign is enumerated bijectively into 30 bits, the 4-character grid into 15 bits, and the transmit power into a 5-bit index (the 19 standard WSPR dBm levels), filling exactly the 50 WSPR source bits. The full callsign is transmitted in every frame, so no hash table is used and receivers never show "<...>".
- The convolutional code, interleaving, sync vector, and 4-FSK modulation are unchanged, so weak-signal sensitivity is identical to standard WSPR. These transmissions are decodable only by other WSJT-CB stations and are intentionally not compatible with standard WSPR/WSJT-X or wsprnet. 6-character grids are not used in WSPR mode.
- "My callsign" must be a valid CB callsign and "My grid" a 4-character locator for WSPR transmission; the WSPR message is always built as "CALL GRID4 dBm".
- Implementation: packcb/unpackcb in lib/packjt.f90 (TX) with mirrored C packcb/unpackcb in lib/wsprd/wsprd_utils.c and lib/wsprd/wsprsim_utils.c (RX and signal subtraction), wired through lib/wqencode.f90 and MainWindow::WSPR_message(). The bijection was validated with exhaustive boundary sweeps and multi-million-sample round-trip tests, including the full Fortran-encode to C-decode path.

Version 1.3.0 (in development)

This section tracks all updates for release 1.3.0, including the visual redesign already introduced and the next changes that will be added in this repository.

Changes already included

- Complete UI restyling with a modern dark theme.
- New unified visual system (palette, buttons, inputs, menus, tabs, tables, and scrollbars).
- Improved main window chrome: decode panels, headings, borders, and splitters are now more consistent.
- Dark style is now enabled by default at startup for a more modern and coherent UX.
- Main window dimensions were updated for better rendering on current desktop setups.
- Project versioning updated from 1.2.0 to 1.3.0 across the main repository occurrences.
- Application titlebar/branding signature updated to `1AT106 1XZ732 1AT1989`.
- Settings storage now uses a stable `WSJT-CB.ini` base name and migrates legacy branding-based `.ini` files automatically, so titlebar branding changes no longer reset user settings.
- Default logging now uses the same stable application data directory and migrates the previous branding-based log directory automatically.
- Worked-before logbook and country lookup now use the stable writable data directory, so `wsjtcb_log.adi`, `cty.dat`, and `grid.dat` stay aligned with the directory opened from the UI.
- Windows CAT support now includes a restored OmniRig build path: OmniRig is enabled through `WSJT_WITH_OMNIRIG`, generated with Qt ActiveQt/`dumpcpp` or `dumpcpp-qt5`, and exposed again as OmniRig Rig 1 / Rig 2 in the transceiver list when building on Windows.
- The Windows/MSYS2 build chain now builds and packages against Hamlib 4.x, verified with Hamlib 4.7.2~rc in the UCRT64 environment, so the generated installer includes the required Hamlib runtime DLLs alongside the application.
- A repeatable Windows packaging script was added for the 1.3 build: it configures CMake/Ninja for UCRT64, enables OmniRig, stages `dist`, copies required runtime DLLs, verifies dependencies, and creates the Inno Setup installer.
- Settings validation for "My callsign" is now CB-only: the field must match the WSJT-CB CB callsign format (e.g. `N{1,3}L{1,2}N{1,3}` or `N{1,3}L{1,2}/LL`), invalid/non-CB callsigns are highlighted in red, and the configuration cannot be saved until the value is valid.
- Automatic on-air CQ/QSO handling now starts QSOs only with complete CB callsigns: non-standard, non-CB, incomplete, and unresolved hashed replies remain visible in the received messages but are ignored by AutoSeq so CQ operation can continue normally. Directed free-text CB replies that clearly match our callsign are still handled as valid QSO progress.

Version 1.2.0

Version 1.2 is a focused refinement of WSJT-CB 1.0. The main goal of this release is not to add complexity, but to make the CB-oriented workflow cleaner, more reliable,
and more consistent for everyday operation.
Compared with 1.0, version 1.2 improves the way the software handles CB-to-CB contacts,
simplifies the interface by removing features that are less relevant to the project's current direction,
and strengthens packaging and identity across the application.

The most important practical improvement is in contact handling between CB-style callsigns.
In 1.0, some non-standard exchanges could still be fragile, especially around signal reports, free-text parsing, and end-of-QSO messages such as RR73 and 73.
In 1.2, that flow has been tightened so that reports are captured more reliably, duplicate RR73 behavior is avoided,
and CB-to-CB QSOs progress more naturally through the final stages of the exchange.
In real use, this should make logging and AutoSeq behavior feel more dependable and less prone to edge-case confusion.

Another visible improvement is country recognition and decoded text presentation.
Version 1.2 continues the CB-specific country mapping work, but also refines how those results are shown to the operator.
Country lookup has been corrected and cleaned up, including fixes for naming mismatches such as U.S.A.,
and the decoded text display now behaves more gracefully when CB prefixes are recognized.
Unknown CB prefixes are no longer shown with rough placeholder labels, which makes the display cleaner and more professional.

From a usability perspective, 1.2 also makes some opinionated choices.
PSK Reporter spotting is now enabled by default, so a fresh installation is more immediately connected and useful without extra setup.
At the same time, older or less relevant parts of the codebase have been removed, including the Astronomical Data widget, ALLCALL7 filtering logic,
legacy side tools, and several obsolete subprojects and documentation pieces.
This makes the application feel more centered on its intended CB digital-mode use case
rather than carrying forward features from the broader WSJT-X ecosystem that are no longer essential here.

The release also completes a broader identity and distribution pass.
WSJT-CB branding is now more consistent throughout the UI, help menu, logging files, configuration names, and installer-related paths.
The help area has been simplified, a Telegram group entry has been added,
and Windows packaging has been improved with a dedicated 1.2.0 installer configuration and fixes related to country-file lookup in installed environments.
Altogether, version 1.2 feels less like a fork in transition and more like a defined, self-contained application.

In short, version 1.2 is a maturity release.
It does not try to become larger than 1.0; instead, it becomes sharper.
It improves the reliability of CB-specific operating flows, cleans up presentation and country handling, reduces legacy baggage,
and delivers a more coherent WSJT-CB experience from first launch to daily use.
